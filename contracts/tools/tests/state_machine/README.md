# Negative cases for `validate_state_machine.py`

Each YAML here is a small state-machine table with **one** violation. `cases.json` lists them:

```json
[{ "file": "states-missing-failed.yaml", "expect": "states differ from CaseState" }]
```

- `expect` is a substring of one error message the validator must produce for that file. Other errors may appear too (a case built from `_base.yaml` is not a complete table, and one built from the real table may break more than one rule); only the expected one is asserted.
- Optional `spec`: a spec file (relative to this folder) to compare against instead of `specs/001-case-state-machine/spec.md`.
- `_base.yaml` is a minimal starting point (the 13 states and T01–T03) for the Foundational cases; the later cases are copies of `contracts/case-state-machine.yaml` with one change.
- The cases, `cases.json` and `spec-expire-by-system.md` are generated by `generate_cases.py`; never edit them by hand. Regenerate after editing the real table or the spec:

```sh
uv run --with pyyaml python contracts/tools/tests/state_machine/generate_cases.py
```

Run all cases and then the real table (`contracts/case-state-machine.yaml`), from the repo root:

```sh
uv run --with pyyaml python contracts/tools/test_validate_state_machine.py
```

To add a case, add it to `CASES` in `generate_cases.py`, regenerate and watch it fail, then change the validator (TDD).
