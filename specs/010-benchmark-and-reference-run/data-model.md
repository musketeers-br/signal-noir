# Data Model: Benchmark and Reference Run

**Feature**: 010-benchmark-and-reference-run | **Plan**: [plan.md](./plan.md) | **Research**: [research.md](./research.md)

Two persistent records, one port, six pure Core classes and six committed data records. Field names
that appear in `contracts/openapi-signalnoir.yaml` keep the contract's spelling; anything the contract
does not have is marked **(contract change)** and is listed in
[contracts/contract-change-010-benchmark.md](./contracts/contract-change-010-benchmark.md).

## Persistent records (`SignalNoir.Application.Model`)

### BenchmarkRunRecord

| Field | Type | Rules |
|---|---|---|
| `runId` | string, unique | `^run_[A-Za-z0-9_-]{4,64}$`, generated by the application, never by the caller |
| `mode` | `rules` \| `agent` \| `replay` | fixed at creation |
| `purpose` | `benchmark` \| `reference` \| `quick_validation` | fixed at creation |
| `status` | `created` \| `running` \| `completed` \| `failed` | transitions in `Core.Benchmark.RunPolicy` only |
| `provider`, `model` | string \| null | ignored (stored null) in `rules` mode; default from the configured provider otherwise |
| `repetitions` | integer 1–10 | default 3 |
| `seed` | integer ≥ 0 | base seed; per-item seeds derive from it |
| `policyVersion`, `mappingVersion` | string | **pinned** at creation, validated with `Store.For(run)` |
| `scenariosJson` | JSON | the request's selection, after expansion to explicit variants |
| `casesPlanned`, `casesOpened`, `casesTerminal` | integer | progress, counted from the items |
| `development` | boolean | true when `FreezeCheck` says so (never cleared) **(contract change)** |
| `developmentReasonsJson` | JSON array of strings | why; empty when not development **(contract change)** |
| `freezeId`, `freezeJson` | string, JSON | the freeze record in force at creation, copied **(contract change)** |
| `inputsDigestJson` | JSON | the digests of the frozen inputs read at creation and again at the first step |
| `reportJson` | JSON | written once, when `completed`; absent otherwise (FR-024) |
| `label` | string | free text from the request |
| `failureReason` | string \| null | coded: `deadline`, `provider_unavailable_for_run`, `simulator_unreachable`, `abandoned` |
| `createdAt`, `startedAt`, `completedAt`, `heartbeatAt` | UTC ISO-8601 | |

Identity: `runId` unique index. Single active run: enforced in `RunService.Create` under a lock plus a
check of `status IN ('created','running')`.

### BenchmarkItemRecord

| Field | Type | Rules |
|---|---|---|
| `runId`, `itemNo` | string, integer | unique together; `itemNo` is the plan order |
| `family`, `subtype`, `variant`, `set` | string | from the Simulator catalog; `set` is `tuning` or `test` |
| `repetition` | integer ≥ 1 | |
| `seed` | integer | `Core.Benchmark.Seed.For(run.seed, family, variant, repetition)` |
| `scenarioInstanceId` | string \| empty | set when the instance is created |
| `caseId` | string \| empty | set when the Case opens |
| `status` | `planned` \| `opened` \| `ended` \| `not_decided` | |
| `notDecidedReason` | string \| empty | `provider_unavailable`, `run_failed`, `deadline` |
| `deadlineAt` | UTC ISO-8601 | when an `opened` item with no decision becomes `not_decided` (a Case `Approved` or `Executing` by then gets the execution lease more) |

An item never changes a Case. The Case is read by `caseId` through the existing read side.

## Port (`SignalNoir.Core.Port.RunDirectory`)

`Find(runId) → {runId, mode, status, purpose, policyVersion, mappingVersion} | ""`. Implemented by
`Application.Benchmark.RunStore`; a fake in `Tests.Fakes`. Used by `CaseService.NewCase` (D2), the two
automatic-Approval call sites, and `ResolutionValidator.RunFor`.

## Pure Core (`SignalNoir.Core.Benchmark`, no I/O)

| Class | Responsibility | Input → output |
|---|---|---|
| `Seed` | per-item seed | `(baseSeed, family, variant, repetition)` → integer 0 … 2³¹−1 |
| `RunPolicy` | create-time rules and the run state machine | request → `{ok, errors[]}`; `(status, event)` → status |
| `Scorer` | classify one Case against its key | `(key, facts)` → `{outcome, effect, blockedWrongProposals, wrongEffect, reason}` |
| `Stats` | per-repetition values and ranges | rows → `AgentDecisionRow`-shaped values |
| `FreezeCheck` | development / refusal | `(freeze, current, roles, reviews, usage, selection)` → `{development, reasons[]}` |
| `Guarantees` | pass / fail / not exercised | counts → `PlatformGuaranteeRow`-shaped values |

`Scorer.VERSION` is the evaluator version named by the freeze.

### Scorer facts (input, built by the application from persisted records)

```
facts = {
  finalState,                 // Case state at the end of the item
  effect: {action, params} | null,   // the executed Action, null when none was sent
  proposals: [{action, params, verdict}],   // every Proposal of the Case, in order
  touchedByPerson,            // any Timeline event with actor operator:*
  notDecidedReason | null     // from the Investigation / Case reason codes
}
```

### Answer key (one entry per variant)

```
{ "variant": "P5-tune-01",
  "acceptable": [ {"action": "APPLY_APPROVED_MAPPING", "params": {"mappingId": "map_glicj_serum"}} ],
  "reviewIsAcceptable": false,
  "notes": "free text, read by the reviewer, never by the scorer" }
```

`acceptable` may list several Actions; `params` is a subset (every listed key must match, extra keys on
the effect are ignored). `reviewIsAcceptable` is the only place that says review is a right answer.

## State machine of a run

```
created --start--> running --all items ended--> completed
   |                  |
   +----fail--------> failed <----deadline / abandoned----+
```

`completed` and `failed` are terminal. A report exists only in `completed` (and a `failed` run offers
none as a reference result). A run past its deadline moves to `failed` with `failureReason = deadline`.

## What a Case carries (existing fields, now filled by 010)

| Field | Value |
|---|---|
| `CaseRecord.runId` | the run id when the run is `running` at opening, else empty |
| `CaseRecord.proposerMode` | the run's mode, else `agent` |
| `CaseRecord.replay` | true when the run's mode is `replay` |
| `ApprovalRecord` (actor `benchmark`) | only for a Case whose run is `running`; carries the run id |

## Report assembly (not stored per row)

`ReportBuilder.Build(run)` reads the items, the Cases (state, Timeline actors), the Proposals and
Executions, and the Investigations (latency, tool calls, cost, reason); builds `BenchmarkCaseResult` rows;
and passes them to `Scorer`, `Stats` and `Guarantees`. The result is written to `reportJson` once.
`ComparativeBenchmarkReport` is built on demand from two or more stored reports.
