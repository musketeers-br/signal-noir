# Contract change 006 — Investigation seam (seams v3 → v4)

**Status**: proposed by feature 006 (Henry), 2026-10-25. Applied to `docs/seams.md` with the
implementation; reviewed at gate G2.

**Frozen HTTP contracts**: one change, requested by Henry on 2026-10-25 ("always English in
code"): the `Confidence` enum of `contracts/openapi-signalnoir.yaml` goes from `ALTA, MEDIA, BAIXA`
to `HIGH, MEDIUM, LOW`. The fixtures were regenerated by the prototype exporter
(`_bmad-output/initiative-signal-noir/prototype-signal-noir/tools/export-api-fixtures.js`) after the
same change in the prototype; only `confidence` values changed, and all 25 still validate. The PRD
text keeps the Portuguese labels as prose; the contract is the normative source for the values.

## Why

The proposer needs the pre-collected Evidence and the read-only gateway, and its answer must be
converted by one core function for every origin (spec FR-012, FR-014). The v3 `Propose(case)` with a
ready Proposal DTO allows three conversion paths.

## Changes

### Proposer

| v3 | v4 |
|---|---|
| `Propose(case: Case) -> Result<Proposal>` | `Propose(context: InvestigationContext) -> Result<ProposerAnswer>` — `Result.obj` is the raw answer (`%DynamicObject`, data) in the contract's Proposal shape minus ids; `Result.details` carries `provider`, `model`, `promptVersion`, `tokensIn`, `tokensOut`, `estCostUsd` when known. Failure codes: `provider_unavailable`, `invalid_response`, `refused`, `budget_exceeded`. |

### New DTO `InvestigationContext`

`investigationId`, `case` (Case), `order` (Order), `evidence` (list of Evidence collected so far),
`tools` (Tools port, the gateway), `budget` (`maxToolCalls`, `budgetMs`, `startedAt`).

### Evidence DTO

Adds the contract fields: `calledBy`, `params`, `result`, `durationMs`, `suspicious`,
`suspiciousExcerpts`, `obsoletedBy`, and `kind` = `fact` / `absence`. `payload` stays as an alias of
`result` for v3 consumers.

### Proposal DTO

Becomes the contract's Proposal: `proposalId`, `caseId`, `origin` (= author), `createdAt`,
`current`, `supersededBy`, `diagnosis`, `action`, `params`, `scope`, `confidence` (`HIGH` /
`MEDIUM` / `LOW`), `preconditions`,
`versions` (`policy`, `mapping`, `prompt`, `model`, `provider`), `metrics`, `priorReceiptCandidate`.
`basedOnVersions` is removed (replaced by `versions`, already the v2 seam table's name).

### Tools

`Invoke(toolName, args) -> Result<Evidence>` unchanged in signature. The runtime implementation
(`ToolGateway`) accepts only `tool.partner_failure_history`, `tool.policies`, `tool.partner_health`,
`tool.mapping_catalog`, `tool.receipts_and_orders_by_patient`, `tool.origin_order_status`,
`tool.order_timeline`; the returned Evidence is already recorded.

### New internal ports (not for other features)

- `EvidenceSource.Read(toolName, args) -> Result` (`obj` = `{available, result | reason}`)
- `AgentRuntime.Complete(systemPrompt, input) -> Result` (`details.content`, tokens, model, provider)

### Order

Adds `scenarioInstanceId`; `OrderIn.Accept(json, transactionId, runId, scenarioInstanceId)`.

### Fakes

`FakeProposer` returns a configurable answer; `FakeTools` returns Evidence with the new fields.

## Impact

- 004 (Validator): receives the contract-shaped Proposal DTO.
- 009 (Dossier): reads Evidence `kind` to separate fact from absence.
- 010 (Benchmark): selects the mode on the Case; Replay recordings via `Proposers.Replay.Record`.
