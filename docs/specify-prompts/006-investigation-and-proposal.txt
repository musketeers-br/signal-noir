Feature: Investigation and Proposal production.

Describe the behavior:
1. An Investigation is a bounded session for one Case, with a server-enforced budget of at most 6 tool calls and 20 seconds. Exceeding the budget ends in ReviewRequired with the evidence collected so far.
2. Every consultation from any proposer goes through a read-only Tools port. Each call is recorded as Evidence before it returns to the proposer, with source, parameters, result, moment and a suspicious-content marker when applicable.
3. Order, partner and log content is data, never instruction. An embedded instruction must not change the outcome. The attempt and its blocking are recorded as Evidence.
4. A single Proposer port returns the same Proposal DTO for every origin: agent, rules and replay. A Proposal is immutable and has its own proposalId. After the port, no component reads the proposer mode to decide behavior.
5. The agent proposer invokes the AI Hub Agent inside the investigation process, with a new session per Investigation. The agent has only read tools. Its output is data and becomes a Proposal only after conversion to the DTO and validation.
6. The Proposal contains: Diagnosis with claims linked to evidence IDs and discarded hypotheses with reasons; Action and parameters; scope single_case; confidence HIGH/MEDIUM/LOW; preconditions from the closed vocabulary; references to Evidence; versions of policy, prompt, model and provider; and metrics (duration, tool calls, tokens when available, estimated cost).
7. Pre-collected evidence fallback: if the agent cannot call tools in the live build, the system gathers the evidence deterministically and gives it to the agent in one call. The real AI Hub call still happens.
8. Invalid response, refusal, timeout, missing key or provider unavailable ends in ReviewRequired. A late agent response must not change an Investigation that has already closed.
9. The system records model, provider, versions, duration, tool calls and tokens for every Investigation when available.

Acceptance scenarios:
- A P5/P8b Case produces a structured Proposal whose claims reference recorded Evidence.
- The budget is exceeded: ReviewRequired, with the evidence collected so far.
- No write tool exists; the Tools port rejects any write attempt.
- An embedded instruction in an Order or partner response does not change the Action, and the attempt is recorded.
- A late agent response after closure does not change the Case.
- Provider failure or missing key: ReviewRequired, with the reason.
- Rules and agent use the same Tools and the same protections.
- Every tool call is recorded before the proposer sees its result.
- The Proposal carries model, provider, versions, duration, tool calls and tokens when available.

Out of scope: Validator rules, Approval decisions, Execution, the operator console, benchmark scoring.

Success criteria: every Proposal is structured, evidence-linked, immutable and produced under a server-enforced read-only budget; untrusted content cannot steer the system.

Anchors: contracts/openapi-signalnoir.yaml (Evidence, Proposal, metrics); contracts/openapi-sim.yaml (evidence sources).
