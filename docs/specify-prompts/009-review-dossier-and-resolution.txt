Feature: the Review Dossier and operator resolution.

Describe the behavior:
1. When a Case enters ReviewRequired, produce a Review Dossier with: the reason; the partial diagnosis; hypotheses considered and discarded with reasons; the relevant evidence with conflicts highlighted; colliding records and their divergent fields for identity cases; unconfirmed prior-receipt candidates; the suggested next human step; and a list of factual unknowns.
2. The Dossier must work when the agent fails before proposing: it states the reason (provider unavailable, invalid response, budget exceeded or interrupted investigation) and includes the evidence collected so far.
3. The Dossier never contains a query or Evidence that did not happen. Absence of information is rendered as a factual unknown, distinct from a negative conclusion. An empty unknowns list means "nothing flagged", not "everything is known".
4. Operator resolution: from the Dossier, the operator chooses a catalog Action with its parameters or cancels the Case. The chosen Action passes through the same Validator as any Proposal. The operator is recorded as the Proposal author with `operator:<name>`. There is no free payload editing. Cancellation requires a reason.
5. If the Validator refuses the operator's choice, nothing is executed and only the verdict is recorded. The response names the reason codes and keeps the operator's input.
6. A resolved Case follows the same Approval and Execution path as any other Proposal.

Acceptance scenarios:
- Ambiguous identity: the Dossier shows the colliding synthetic records and the divergent fields.
- Budget exceeded, invalid response or provider unavailable: the Dossier names the reason and includes the evidence collected so far.
- LLM fails before any Proposal: the Dossier still explains why automation stopped and contains no invented query or evidence.
- Empty unknowns: "nothing flagged", never "everything is known".
- Operator chooses a valid catalog Action: it passes the same Validator, the operator is recorded as author, and the normal Approval/Execution path follows.
- Operator chooses an invalid Action or parameters: 422 with reason codes, nothing executed, form values kept.
- Cancellation without a reason: refused. With a reason: recorded.
- No free payload field exists anywhere in the resolution path.

Out of scope: the console presentation (005), the Validator core (004), Execution (008), Benchmark scoring.

Success criteria: every ReviewRequired Case has an actionable Dossier; no Dossier invents information; every human resolution passes the same Validator and records its author.
