Feature: Case Precedents, a vector search over closed Cases.

Describe the behavior:
1. Every Case that reaches a final state becomes a precedent exactly once, described only by structured facts (partner, exam code, exception class, Action taken, final state, time to close). Free text from an Order, a partner, an Operator or the Agent is never part of it. Benchmark and Replay Cases are not indexed by default.
2. An Operator who opens a Case, especially one in ReviewRequired, sees "Similar resolved Cases": up to five precedents by similarity, each with its Action, final state, time to close, similarity and a link. In the Review Dossier it sits next to the next-step box.
3. Precedents are information for the Operator, never Evidence and never a decision. They do not reach the Validator, do not count towards the minimum Evidence, are not claims of a Diagnosis, do not pre-fill a resolution and are not reasons in an Approval. With the feature on or off, Proposals, verdicts, Approvals and resolutions for the same Cases are identical.
4. Honest outcomes with distinct messages: no precedents yet, nothing similar enough, lexical mode (no embedding provider key), index rebuilding, index needs rebuild, search unavailable with its reason. Without a provider key the application starts, Case flows are unchanged, and the search runs in a labelled lexical mode that is never presented as semantic.
5. Every search leaves one Timeline event (requester, mode, model, result count, precedent identifiers, duration, failure reason), rate-limited to one per minute per Case and requester, with no key and no free text.
6. Records keep the model, mode and dimension that built them; searches never mix models; an administrator can rebuild all precedents idempotently and resumably.
7. Optional, off by default and off in the frozen reference run: a read-only Agent Tool that returns precedents marked as similarity results, excludes the Case itself and Cases of the same BenchmarkRun, and is never accepted as Evidence. If enabled in any Benchmark run, the report says so and publishes it as a separate variant.
8. The embedding provider is configured separately from the Agent's provider, because not every AI Hub provider offers embeddings.
